# Reference examples

Three handlers and the settings block that registers them — a real working hook composition, not a template. Each one is a different kind of event responsibility: `format-touched.sh` **reacts** (after every Edit/Write the touched Python file comes out formatted, and it always exits 0 because formatting is a courtesy and `PostToolUse` cannot block anyway); `stop-gate.sh` **gates** (when the agent tries to finish, green checks let it, red checks block with the failure as the reason); `baton.sh` **hands off** (one skill's artifact starts the next skill in a fresh context, asynchronously). `settings.json` shows how the three are wired to `PostToolUse` and `Stop`, including the `"async": true` on the baton.

Read them for the guard discipline, which is the real lesson: every handler reads **state**, not memory, so it can fire a hundred times and act once. Then change two things for your own project. The check chain in `stop-gate.sh` (and the `app/backend` directory it runs in) must become your project's authoritative checks — and keep the exit-code translation, since your checkers exit 1 on failure and only **exit 2** blocks. The other is `baton.sh`'s state paths: the input artifact glob, the done-marker that doubles as the recursion guard, and the in-flight marker are all AI-Tutor-specific, and the guard is only correct if those three point at real state in your repository. Event names, the settings file, and the blocking mechanism are Claude Code's; on another agent they are the first thing to re-verify.
